# 饭饭小地图 🍙

把好吃的，圈进小地图。面向深圳日常活动的个人美食微信小程序，中文界面，奶油白、桃粉、明黄和薄荷绿的手帐风格。

## 先在电脑本地运行

本地版已提供浏览器入口，使用 SQLite 和本机照片文件。准备 Node.js 24 或更新版本，在项目根目录运行。

```sh
npm install
npm start
```

打开 http://localhost:3000 。修改服务端代码时可使用 `npm run dev` 自动重启。端口被占用时可用 `PORT=3001 npm start`，然后访问对应端口。

- 点击“记一口好吃的”，填写店名，在地图上点选位置，添加口味、照片、推荐菜和喜欢程度。
- 点击“定位到我”并允许浏览器访问位置。定位不可用时，点击“设置我的位置”，在主地图上点选你所在的位置。
- 距离由真实经纬度计算，目前显示直线距离。实际道路里程和交通用时可在后续接入路线服务。
- 地图使用 Leaflet 与可免 Key 访问的 Esri World Street Map 底图。底图需要联网，页面包含来源标注。网络异常时自动显示项目内置的深圳行政区轮廓，仍可选点、记录和计算距离。内置轮廓数据来自 [DataV GeoAtlas](https://geo.datav.aliyun.com/areas_v3/bound/440300_full.json)。
- 小勇者、小公主是这台电脑上的两个本地档案，分别保存自己的记录。角色插画和三级喜欢已内置。
- 浏览器语音输入使用浏览器支持的语音识别服务，可能需要联网和麦克风授权。服务不可用时页面会给出文字输入提示。

本地数据保存在 `.local/food-map.sqlite`，照片在 `.local/uploads/`，已加入 Git 忽略。备份时先停止服务，再复制整个 `.local/` 文件夹。本地版启动入口只监听 `127.0.0.1`，浏览器地址适用于当前电脑。

本地版通过独立接口保存与微信版一致的店铺、菜品和照片字段。浏览器地图与定位记录 WGS-84 坐标，微信版使用 GCJ-02，未来迁移数据时需要按坐标来源转换。

浏览器新增草稿保存在当前浏览器，保存成功的记录和照片保存在 SQLite 与本机文件中。保存响应中断时保留同一请求，重试确认后继续编辑。

开发检查可以运行以下命令。浏览器检查使用本机安装的 Google Chrome，在临时数据库中模拟定位和保存中断，完成后删除测试数据，截图保存在忽略目录 `.local/debug/`。

```sh
npm test
npm run check
npm run test:browser
```

本地版运行与调试已覆盖地图选点、直线距离、店铺／菜单／菜品照片、编辑、三级喜欢、搜索、档案隔离、刷新与服务重启后的持久化、保存响应中断重试及手机布局。浏览器真实定位取决于系统和浏览器授权，语音服务可用性仍需在实际网络和设备上确认。

## 功能

- 微信身份登录，云端同步个人店铺与菜品，用户数据隔离。
- 原生微信地图选点、店铺标记、前台实时定位、直线距离排序，卡片同时显示地图计算的步行路线距离与用时。
- 按店名、口味、推荐菜搜索，按美食分类筛选。
- 步行、骑行、驾车、公交路线查询，路线距离、预计用时与到达时刻，打开微信位置导航。
- 普通话语音填写店名或备注，转写后可修改。
- 店铺照片、菜单照片和每道推荐菜独立照片，拍照与相册选择。
- 三级喜欢程度“有点喜欢 / 很喜欢 / 超级喜欢”，绿、蓝、红宝石与递进笑容表达喜爱。兼容已有五星评分。
- 原创小勇者 / 小公主角色偏好按微信账户云端同步，各自选择自己的冒险形象。
- 口味标签、菜品价格及评价，编辑和删除。
- 离线浏览已同步的列表缓存，新增记录本地草稿，网络未确认时保留幂等请求以便重试。

## 微信小程序后续导入配置

需要微信开发者工具、小程序 AppID，以及该 AppID 下的微信云开发环境。当前源码的 `touristappid` 便于识别配置位置，云功能必须使用实际 AppID。

1. 微信开发者工具导入仓库根目录，将 `project.config.json` 的 `appid` 改为自己的小程序 AppID。
2. 开通微信云开发，将 `miniprogram/config.js` 的 `env` 填为云环境 ID。
3. 在云数据库创建 `users`、`restaurants`、`save_requests` 三个集合。分别将权限改为自定义规则，粘贴根目录 `database.rules.json` 内容。数据由云函数校验身份后访问。
4. 为 `restaurants` 创建组合索引 `_openid` 升序与 `_id` 升序，支持个人分页查询。
5. 云存储权限设置为“仅创建者可读写”，自定义规则示例见 `storage.rules.json`。上传需保持微信用户身份上下文。
6. 右键 `cloudfunctions/api`，选择“上传并部署，云端安装依赖”。Node.js 运行环境选择 18 或更高，超时 20 秒，内存至少 256 MB。
7. 在腾讯位置服务申请 WebService key，开通步行、骑行、驾车与公交路线权限。为 `api` 云函数设置环境变量 `TENCENT_MAP_KEY`，重新部署。若启用腾讯地图签名校验，需另行适配签名参数或使用服务支持的密钥校验配置。
8. 微信公众平台添加“微信同声传译”插件，提供方 AppID `wx069ba97219f66d99`，对应 `app.json` 中 WechatSI 版本 `0.3.5`。以公众平台可授权版本为准。如暂不接语音，移除 `app.json` 的 `plugins` 配置，并将 `config.js` 的 `voiceEnabled` 改为 `false`，其余功能可运行。
9. 微信公众平台按实际用途配置用户隐私保护指引，声明位置、选点、持续前台定位、录音及照片功能，并申请当前类目所需的位置接口权限。用真机体验版验证授权和插件。

腾讯地图请求由云函数发起。地图初始视角为深圳，保存位置支持中国大陆坐标，使用 GCJ-02，与微信地图一致。路线可用性取决于腾讯地图服务和实际地点，失败时页面会给出反馈。

## 使用

首次打开地图后授权定位。在“记一口”选店铺位置，填写店名和口味，添加照片、菜单或推荐菜并保存。进入店铺详情可切换交通方式。语音按钮点击开始，再次点击结束，识别文字可继续编辑。语音填写店名会替换当前店名。

记录保存在云端。头像与昵称可选，当前仅保存在手机本地。无定位权限时仍能浏览记录，距离显示“待定位”。首次使用为空白地图，不预置示例店铺。

保存请求获得云端确认前，编辑内容会锁定，点击“重试确认上一笔保存”使用相同请求编号继续。不要手工清除应用缓存，否则会丢失待确认请求和本地草稿。失败上传的图片会尽力清理，网络异常或云端清理失败可能留下孤立文件，可在云存储控制台检查。

## 原创角色插画

按用户选择采用原创小勇者与小公主，两套角色各有三级获得宝石后的开心表情，分别对应“有点喜欢 / 很喜欢 / 超级喜欢”。插画已内置在 `miniprogram/assets/`，在编辑页、店铺卡片、详情和角色选择中使用。图片经过尺寸与体积优化，保持三等分图集布局。角色选择单独按微信身份同步。初次使用默认小勇者，可在“我的食光”切换。

## 本地检查

```sh
npm test
npm run check
```

根目录检查使用 Node.js 24+ 内置测试器与 SQLite。先运行 `npm install` 安装本地服务依赖，云函数依赖由微信开发者工具云端安装。

覆盖距离与到达时刻计算、输入校验、用户所有权、版本冲突、上传失败清理和云端错误分类。JS 语法与配置检查覆盖所有页面与云函数。

真实微信编译、前台持续定位、云端权限、照片同步、语音插件、各交通模式路线均需要上述服务配置和真机验收。当前开发环境未连接小程序 AppID 与云环境，不能据本地检查推断真机功能已验收。

## 目录

```text
local/                本地浏览器页面、SQLite 数据访问与服务
miniprogram/           原生微信小程序
  pages/map/          地图、搜索、筛选、定位
  pages/edit/         店铺、菜品、照片、语音编辑
  pages/detail/       详情、路线、导航
  pages/profile/      个人美食统计与列表
  services/api.js     云调用、缓存与照片上传
  utils/domain.js     数据校验、距离和时刻计算
cloudfunctions/api/   微信身份、个人数据、事务保存与路线代理
tests/                核心逻辑回归测试
docs/superpowers/     已确认设计与执行计划
```

`save_requests` 保存不可变的请求回执，和店铺更新在同一事务提交，用于网络重试与跨设备编辑场景。每条记录带版本号，冲突时请重新打开最新记录再编辑。
